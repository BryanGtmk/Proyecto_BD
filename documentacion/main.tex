\section{Informe de guía práctica}

\subsection{Objetivos}

\subsubsection{General}

Implementar bases de datos en Oracle mediante el uso de sentencias DDL, restricciones de integridad, claves primarias, claves foráneas, modificación de estructura y recuperación de tablas eliminadas.

\subsubsection{Específicos}

\begin{itemize}
    \item Crear tablas en Oracle utilizando claves primarias, claves foráneas y restricciones.
    \item Insertar datos de prueba para comprobar el funcionamiento de las relaciones entre tablas.
    \item Aplicar comandos \texttt{ALTER TABLE}, \texttt{DROP TABLE} y \texttt{FLASHBACK TABLE} para modificar y recuperar estructuras.
\end{itemize}

\subsection{Modalidad}

La práctica se desarrolló de forma individual, utilizando Oracle como gestor de base de datos y sentencias SQL para la implementación de los dos ejercicios propuestos.

\subsection{Actividades por desarrollar}

\subsubsection{Ejercicio 1: Sistema de Inventario Académico}

El primer ejercicio se desarrolló para controlar artículos académicos dentro de una institución. Para ello se utilizaron tablas como \texttt{CATEGORIA}, \texttt{DEPARTAMENTO}, \texttt{ESTADO\_ARTICULO}, \texttt{ROL}, \texttt{USUARIO}, \texttt{UBICACION}, \texttt{RESPONSABLE}, \texttt{ARTICULO}, \texttt{PRESTAMO} y \texttt{DETALLE\_PRESTAMO}.

\subsubsection{Creación del usuario}

Primero se creó un usuario propio para trabajar la base de datos del inventario académico. Luego se asignaron permisos de conexión, creación de objetos y uso de espacio.

\begin{lstlisting}[style=sqlstyle]
CONNECT system/system;

CREATE USER INV_ACADEMICO IDENTIFIED BY INV123;
GRANT CONNECT, RESOURCE, UNLIMITED TABLESPACE TO INV_ACADEMICO;

CONNECT INV_ACADEMICO/INV123;
\end{lstlisting}

\subsubsection{Fase P1: Creación de tablas base}

En esta fase se crean las tablas principales de catálogo. Estas tablas sirven como base para clasificar los artículos, identificar los departamentos y registrar los estados posibles de cada artículo.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE CATEGORIA (
    ID_CAT      NUMBER(10) PRIMARY KEY,
    NOM_CAT     VARCHAR2(40) NOT NULL UNIQUE,
    DES_CAT     VARCHAR2(100)
);

CREATE TABLE DEPARTAMENTO (
    ID_DEP      NUMBER(10) PRIMARY KEY,
    NOM_DEP     VARCHAR2(50) NOT NULL UNIQUE,
    UBIC_DEP    VARCHAR2(50) NOT NULL
);

CREATE TABLE ESTADO_ARTICULO (
    ID_EST      NUMBER(10) PRIMARY KEY,
    NOM_EST     VARCHAR2(30) NOT NULL UNIQUE,
    CONSTRAINT CHK_ESTADO_ARTICULO 
    CHECK (NOM_EST IN ('DISPONIBLE','PRESTADO','MANTENIMIENTO','BAJA'))
);
\end{lstlisting}

La tabla \texttt{CATEGORIA} permite clasificar los artículos. La tabla \texttt{DEPARTAMENTO} permite registrar las áreas de la institución. La tabla \texttt{ESTADO\_ARTICULO} controla que los artículos solamente puedan tener estados válidos.

\subsubsection{Fase P2: Creación de tablas con restricciones}

En esta fase se crean las tablas que permiten registrar roles, usuarios, ubicaciones y responsables. Se aplican restricciones como \texttt{PRIMARY KEY}, \texttt{UNIQUE}, \texttt{NOT NULL}, \texttt{CHECK} y claves foráneas.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE ROL (
    ID_ROL      NUMBER(10) PRIMARY KEY,
    NOM_ROL     VARCHAR2(30) NOT NULL UNIQUE,
    CONSTRAINT CHK_ROL 
    CHECK (NOM_ROL IN ('ADMINISTRADOR','DOCENTE','ESTUDIANTE','ASISTENTE'))
);

CREATE TABLE USUARIO (
    CED_USU      VARCHAR2(10) PRIMARY KEY,
    NOM_USU      VARCHAR2(30) NOT NULL,
    APE_USU      VARCHAR2(30) NOT NULL,
    COR_USU      VARCHAR2(60) UNIQUE,
    ID_ROL_PER   NUMBER(10) NOT NULL,
    EST_USU      VARCHAR2(10) DEFAULT 'ACTIVO' NOT NULL,
    CONSTRAINT CHK_EST_USUARIO 
    CHECK (EST_USU IN ('ACTIVO','INACTIVO')),
    FOREIGN KEY (ID_ROL_PER) REFERENCES ROL(ID_ROL)
);

CREATE TABLE UBICACION (
    ID_UBI       NUMBER(10) PRIMARY KEY,
    NOM_UBI      VARCHAR2(50) NOT NULL,
    ID_DEP_PER   NUMBER(10) NOT NULL,
    FOREIGN KEY (ID_DEP_PER) REFERENCES DEPARTAMENTO(ID_DEP)
);

CREATE TABLE RESPONSABLE (
    CED_RES      VARCHAR2(10) PRIMARY KEY,
    NOM_RES      VARCHAR2(30) NOT NULL,
    APE_RES      VARCHAR2(30) NOT NULL,
    TEL_RES      VARCHAR2(10),
    ID_DEP_PER   NUMBER(10) NOT NULL,
    FOREIGN KEY (ID_DEP_PER) REFERENCES DEPARTAMENTO(ID_DEP)
);
\end{lstlisting}

La tabla \texttt{USUARIO} se relaciona con \texttt{ROL}. La tabla \texttt{UBICACION} se relaciona con \texttt{DEPARTAMENTO}. La tabla \texttt{RESPONSABLE} también depende de un departamento, porque cada responsable pertenece a un área específica.

\subsubsection{Fase P3: Creación de tablas relacionadas}

En esta fase se crean las tablas principales del proceso. La tabla \texttt{ARTICULO} almacena los bienes académicos. La tabla \texttt{PRESTAMO} registra la cabecera del préstamo. La tabla \texttt{DETALLE\_PRESTAMO} registra los artículos incluidos en cada préstamo.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE ARTICULO (
    COD_ART       VARCHAR2(10) PRIMARY KEY,
    NOM_ART       VARCHAR2(60) NOT NULL,
    MAR_ART       VARCHAR2(30),
    MOD_ART       VARCHAR2(30),
    FEC_ADQ       DATE NOT NULL,
    VAL_ART       NUMBER(10,2) NOT NULL,
    ID_CAT_PER    NUMBER(10) NOT NULL,
    ID_EST_PER    NUMBER(10) NOT NULL,
    ID_UBI_PER    NUMBER(10) NOT NULL,
    CED_RES_PER   VARCHAR2(10) NOT NULL,
    CONSTRAINT CHK_VAL_ART CHECK (VAL_ART > 0),
    FOREIGN KEY (ID_CAT_PER) REFERENCES CATEGORIA(ID_CAT),
    FOREIGN KEY (ID_EST_PER) REFERENCES ESTADO_ARTICULO(ID_EST),
    FOREIGN KEY (ID_UBI_PER) REFERENCES UBICACION(ID_UBI),
    FOREIGN KEY (CED_RES_PER) REFERENCES RESPONSABLE(CED_RES)
);

CREATE TABLE PRESTAMO (
    ID_PRE        NUMBER(10) PRIMARY KEY,
    FEC_PRE       DATE DEFAULT SYSDATE NOT NULL,
    FEC_DEV_PREV  DATE NOT NULL,
    CED_USU_PER   VARCHAR2(10) NOT NULL,
    CED_RES_PER   VARCHAR2(10) NOT NULL,
    EST_PRE       VARCHAR2(20) DEFAULT 'ABIERTO' NOT NULL,
    CONSTRAINT CHK_EST_PRESTAMO 
    CHECK (EST_PRE IN ('ABIERTO','DEVUELTO','ATRASADO','CANCELADO')),
    FOREIGN KEY (CED_USU_PER) REFERENCES USUARIO(CED_USU),
    FOREIGN KEY (CED_RES_PER) REFERENCES RESPONSABLE(CED_RES)
);

CREATE TABLE DETALLE_PRESTAMO (
    ID_DET        NUMBER(10) PRIMARY KEY,
    ID_PRE_PER    NUMBER(10) NOT NULL,
    COD_ART_PER   VARCHAR2(10) NOT NULL,
    FEC_DEV_REAL  DATE,
    OBS_DET       VARCHAR2(100),
    FOREIGN KEY (ID_PRE_PER) REFERENCES PRESTAMO(ID_PRE),
    FOREIGN KEY (COD_ART_PER) REFERENCES ARTICULO(COD_ART),
    CONSTRAINT UQ_DETALLE_ARTICULO UNIQUE (ID_PRE_PER, COD_ART_PER)
);
\end{lstlisting}

La tabla \texttt{ARTICULO} tiene varias claves foráneas porque depende de categoría, estado, ubicación y responsable. La tabla \texttt{PRESTAMO} se relaciona con el usuario que solicita el préstamo y con el responsable que lo gestiona. Finalmente, \texttt{DETALLE\_PRESTAMO} une el préstamo con los artículos prestados.

\subsubsection{Consultas de comprobación}

Para comprobar que la información fue registrada correctamente, se ejecutan consultas sobre cada tabla.

\begin{lstlisting}[style=sqlstyle]
SELECT * FROM CATEGORIA;
SELECT * FROM DEPARTAMENTO;
SELECT * FROM ESTADO_ARTICULO;
SELECT * FROM ROL;

SELECT * FROM DETALLE_PRESTAMO;
\end{lstlisting}

Estas consultas permiten verificar que las tablas existen y que los registros fueron insertados correctamente.

\subsubsection{Consulta con JOIN}

La siguiente consulta permite mostrar artículos prestados junto con el usuario y el responsable. Para lograrlo se relacionan las tablas \texttt{DETALLE\_PRESTAMO}, \texttt{ARTICULO}, \texttt{PRESTAMO}, \texttt{USUARIO} y \texttt{RESPONSABLE}.

\begin{lstlisting}[style=sqlstyle]
SELECT 
    DP.ID_DET,
    A.NOM_ART AS ARTICULO,
    U.NOM_USU || ' ' || U.APE_USU AS USUARIO,
    R.NOM_RES || ' ' || R.APE_RES AS RESPONSABLE,
    P.EST_PRE
FROM DETALLE_PRESTAMO DP
JOIN ARTICULO A ON DP.COD_ART_PER = A.COD_ART
JOIN PRESTAMO P ON DP.ID_PRE_PER = P.ID_PRE
JOIN USUARIO U ON P.CED_USU_PER = U.CED_USU
JOIN RESPONSABLE R ON P.CED_RES_PER = R.CED_RES;
\end{lstlisting}

Esta consulta sirve para obtener información completa del préstamo, ya que une los datos del artículo, usuario, responsable y estado del préstamo.

\subsubsection{Consulta sin JOIN}

También se realizó una consulta sin utilizar \texttt{JOIN}. En este caso se usó una subconsulta para mostrar los artículos que han sido prestados.

\begin{lstlisting}[style=sqlstyle]
SELECT COD_ART, NOM_ART
FROM ARTICULO
WHERE COD_ART IN (
    SELECT COD_ART_PER
    FROM DETALLE_PRESTAMO
);
\end{lstlisting}

Esta consulta busca en la tabla \texttt{ARTICULO} solamente aquellos códigos que existen dentro de la tabla \texttt{DETALLE\_PRESTAMO}.

\subsubsection{Fase P4: ALTER TABLE, DROP TABLE y FLASHBACK}

En esta fase se modifica la estructura de la tabla \texttt{ARTICULO}, agregando una nueva columna, cambiando el tamaño de una columna existente y agregando una restricción \texttt{UNIQUE}.

\begin{lstlisting}[style=sqlstyle]
ALTER TABLE ARTICULO ADD SERIE_ART VARCHAR2(30);

ALTER TABLE ARTICULO MODIFY NOM_ART VARCHAR2(80);

ALTER TABLE ARTICULO ADD CONSTRAINT UQ_SERIE_ART UNIQUE (SERIE_ART);

UPDATE ARTICULO SET SERIE_ART = 'SERIE-HP-001' WHERE COD_ART = 'A01';
UPDATE ARTICULO SET SERIE_ART = 'SERIE-EP-002' WHERE COD_ART = 'A02';
UPDATE ARTICULO SET SERIE_ART = 'SERIE-SI-003' WHERE COD_ART = 'A03';
UPDATE ARTICULO SET SERIE_ART = 'SERIE-CI-004' WHERE COD_ART = 'A04';
UPDATE ARTICULO SET SERIE_ART = 'SERIE-OL-005' WHERE COD_ART = 'A05';

COMMIT;
\end{lstlisting}

Con esto se demuestra que una tabla ya creada puede modificarse sin necesidad de eliminarla. Además, la restricción \texttt{UNIQUE} evita que se repita el número de serie de los artículos.

Luego se creó una tabla temporal, se eliminó y se recuperó con \texttt{FLASHBACK}.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE PRUEBA_FLASHBACK_INV (
    ID_PRU      NUMBER(10) PRIMARY KEY,
    NOM_PRU     VARCHAR2(30)
);

INSERT INTO PRUEBA_FLASHBACK_INV VALUES (1,'DATO DE PRUEBA');
COMMIT;

DROP TABLE PRUEBA_FLASHBACK_INV;

FLASHBACK TABLE PRUEBA_FLASHBACK_INV TO BEFORE DROP;

SELECT * FROM PRUEBA_FLASHBACK_INV;
\end{lstlisting}

Esta parte permite comprobar que Oracle puede recuperar una tabla eliminada, siempre que no se haya usado \texttt{DROP TABLE ... PURGE}.

\subsubsection{Ejercicio 2: Sistema de Biblioteca}

El segundo ejercicio corresponde a un sistema de biblioteca. Este sistema permite registrar libros, categorías, editoriales, autores, lectores, bibliotecarios, ejemplares y préstamos.

\subsubsection{Creación del usuario}

Se creó un usuario diferente para separar la base de datos de biblioteca de la base de datos del inventario académico.

\begin{lstlisting}[style=sqlstyle]
CONNECT system/system;

CREATE USER BIBLIOTECA_ACAD IDENTIFIED BY BIB123;
GRANT CONNECT, RESOURCE, UNLIMITED TABLESPACE TO BIBLIOTECA_ACAD;

CONNECT BIBLIOTECA_ACAD/BIB123;
\end{lstlisting}

\subsubsection{Fase P1: Creación de tablas base}

En esta fase se crean tablas base para clasificar libros, editoriales, autores y estados de ejemplares.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE CATEGORIA_LIBRO (
    ID_CAT_LIB     NUMBER(10) PRIMARY KEY,
    NOM_CAT_LIB    VARCHAR2(40) NOT NULL UNIQUE,
    DES_CAT_LIB    VARCHAR2(100)
);

CREATE TABLE EDITORIAL (
    ID_EDI      NUMBER(10) PRIMARY KEY,
    NOM_EDI     VARCHAR2(50) NOT NULL UNIQUE,
    DIR_EDI     VARCHAR2(80)
);

CREATE TABLE AUTOR (
    ID_AUT      NUMBER(10) PRIMARY KEY,
    NOM_AUT     VARCHAR2(30) NOT NULL,
    APE_AUT     VARCHAR2(30) NOT NULL,
    NAC_AUT     VARCHAR2(30)
);

CREATE TABLE ESTADO_EJEMPLAR (
    ID_EST_EJE     NUMBER(10) PRIMARY KEY,
    NOM_EST_EJE    VARCHAR2(30) NOT NULL UNIQUE
);
\end{lstlisting}

Estas tablas son necesarias porque los libros dependen de una categoría, una editorial y un autor. Además, cada ejemplar necesita tener un estado.

\subsubsection{Fase P2: Aplicación de restricciones}

En esta fase se crean las tablas \texttt{LECTOR} y \texttt{BIBLIOTECARIO}. Se aplican restricciones para evitar datos incorrectos.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE LECTOR (
    CED_LEC      VARCHAR2(10) PRIMARY KEY,
    NOM_LEC      VARCHAR2(30) NOT NULL,
    APE_LEC      VARCHAR2(30) NOT NULL,
    TEL_LEC      VARCHAR2(10),
    DIR_LEC      VARCHAR2(50),
    COR_LEC      VARCHAR2(60) UNIQUE,
    EST_LEC      VARCHAR2(10) DEFAULT 'ACTIVO' NOT NULL,
    CONSTRAINT CHK_EST_LECTOR 
    CHECK (EST_LEC IN ('ACTIVO','INACTIVO'))
);

CREATE TABLE BIBLIOTECARIO (
    CED_BIB      VARCHAR2(10) PRIMARY KEY,
    NOM_BIB      VARCHAR2(30) NOT NULL,
    APE_BIB      VARCHAR2(30) NOT NULL,
    TUR_BIB      VARCHAR2(15) NOT NULL,
    CONSTRAINT CHK_TURNO_BIB 
    CHECK (TUR_BIB IN ('MATUTINO','VESPERTINO','NOCTURNO'))
);
\end{lstlisting}

La restricción \texttt{CHECK} en \texttt{LECTOR} permite que el estado sea únicamente \texttt{ACTIVO} o \texttt{INACTIVO}. En \texttt{BIBLIOTECARIO}, el turno solo puede ser \texttt{MATUTINO}, \texttt{VESPERTINO} o \texttt{NOCTURNO}.

\subsubsection{Fase P3: Implementación de relaciones}

En esta fase se crean las tablas principales del sistema: \texttt{LIBRO}, \texttt{EJEMPLAR}, \texttt{PRESTAMO\_LIBRO} y \texttt{DETALLE\_PRESTAMO\_LIBRO}.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE LIBRO (
    COD_LIB        VARCHAR2(10) PRIMARY KEY,
    TIT_LIB        VARCHAR2(80) NOT NULL,
    ANIO_LIB       NUMBER(4) NOT NULL,
    ID_CAT_PER     NUMBER(10) NOT NULL,
    ID_EDI_PER     NUMBER(10) NOT NULL,
    ID_AUT_PER     NUMBER(10) NOT NULL,
    CONSTRAINT CHK_ANIO_LIB CHECK (ANIO_LIB >= 1900),
    FOREIGN KEY (ID_CAT_PER) REFERENCES CATEGORIA_LIBRO(ID_CAT_LIB),
    FOREIGN KEY (ID_EDI_PER) REFERENCES EDITORIAL(ID_EDI),
    FOREIGN KEY (ID_AUT_PER) REFERENCES AUTOR(ID_AUT)
);

CREATE TABLE EJEMPLAR (
    ID_EJE        NUMBER(10) PRIMARY KEY,
    COD_LIB_PER   VARCHAR2(10) NOT NULL,
    COD_BARRA     VARCHAR2(20) NOT NULL UNIQUE,
    ID_EST_PER    NUMBER(10) NOT NULL,
    FOREIGN KEY (COD_LIB_PER) REFERENCES LIBRO(COD_LIB),
    FOREIGN KEY (ID_EST_PER) REFERENCES ESTADO_EJEMPLAR(ID_EST_EJE)
);

CREATE TABLE PRESTAMO_LIBRO (
    ID_PRE_LIB     NUMBER(10) PRIMARY KEY,
    FEC_PRE_LIB    DATE DEFAULT SYSDATE NOT NULL,
    FEC_DEV_PREV   DATE NOT NULL,
    CED_LEC_PER    VARCHAR2(10) NOT NULL,
    CED_BIB_PER    VARCHAR2(10) NOT NULL,
    EST_PRE_LIB    VARCHAR2(20) DEFAULT 'ABIERTO' NOT NULL,
    CONSTRAINT CHK_EST_PRE_LIB 
    CHECK (EST_PRE_LIB IN ('ABIERTO','DEVUELTO','ATRASADO','CANCELADO')),
    FOREIGN KEY (CED_LEC_PER) REFERENCES LECTOR(CED_LEC),
    FOREIGN KEY (CED_BIB_PER) REFERENCES BIBLIOTECARIO(CED_BIB)
);

CREATE TABLE DETALLE_PRESTAMO_LIBRO (
    ID_DET_LIB      NUMBER(10) PRIMARY KEY,
    ID_PRE_LIB_PER  NUMBER(10) NOT NULL,
    ID_EJE_PER      NUMBER(10) NOT NULL,
    FEC_DEV_REAL    DATE,
    OBS_DET_LIB     VARCHAR2(100),
    FOREIGN KEY (ID_PRE_LIB_PER) REFERENCES PRESTAMO_LIBRO(ID_PRE_LIB),
    FOREIGN KEY (ID_EJE_PER) REFERENCES EJEMPLAR(ID_EJE),
    CONSTRAINT UQ_DET_LIBRO UNIQUE (ID_PRE_LIB_PER, ID_EJE_PER)
);
\end{lstlisting}

La tabla \texttt{LIBRO} se relaciona con categoría, editorial y autor. La tabla \texttt{EJEMPLAR} representa cada copia física de un libro. La tabla \texttt{PRESTAMO\_LIBRO} registra el préstamo y la tabla \texttt{DETALLE\_PRESTAMO\_LIBRO} indica qué ejemplar fue prestado.

\subsubsection{Consulta con JOIN}

La siguiente consulta muestra los lectores que han realizado préstamos y el bibliotecario que atendió cada préstamo.

\begin{lstlisting}[style=sqlstyle]
SELECT 
    PL.ID_PRE_LIB,
    L.NOM_LEC || ' ' || L.APE_LEC AS LECTOR,
    B.NOM_BIB || ' ' || B.APE_BIB AS BIBLIOTECARIO,
    PL.FEC_PRE_LIB,
    PL.EST_PRE_LIB
FROM PRESTAMO_LIBRO PL
JOIN LECTOR L ON PL.CED_LEC_PER = L.CED_LEC
JOIN BIBLIOTECARIO B ON PL.CED_BIB_PER = B.CED_BIB;
\end{lstlisting}

Esta consulta une las tablas \texttt{PRESTAMO\_LIBRO}, \texttt{LECTOR} y \texttt{BIBLIOTECARIO} para mostrar información más completa del préstamo.

\subsubsection{Consulta de libros prestados}

La siguiente consulta muestra los libros que fueron prestados, junto con el lector y el estado del préstamo.

\begin{lstlisting}[style=sqlstyle]
SELECT 
    DPL.ID_DET_LIB,
    LI.TIT_LIB AS LIBRO,
    LE.NOM_LEC || ' ' || LE.APE_LEC AS LECTOR,
    PL.EST_PRE_LIB
FROM DETALLE_PRESTAMO_LIBRO DPL
JOIN EJEMPLAR E ON DPL.ID_EJE_PER = E.ID_EJE
JOIN LIBRO LI ON E.COD_LIB_PER = LI.COD_LIB
JOIN PRESTAMO_LIBRO PL ON DPL.ID_PRE_LIB_PER = PL.ID_PRE_LIB
JOIN LECTOR LE ON PL.CED_LEC_PER = LE.CED_LEC;
\end{lstlisting}

Esta consulta es importante porque permite identificar qué libro fue prestado, a quién se le prestó y cuál es el estado del préstamo.

\subsubsection{Consulta sin JOIN}

También se realizó una consulta sin usar \texttt{JOIN}. En este caso se usan subconsultas para mostrar los libros que han sido prestados.

\begin{lstlisting}[style=sqlstyle]
SELECT COD_LIB, TIT_LIB
FROM LIBRO
WHERE COD_LIB IN (
    SELECT COD_LIB_PER
    FROM EJEMPLAR
    WHERE ID_EJE IN (
        SELECT ID_EJE_PER
        FROM DETALLE_PRESTAMO_LIBRO
    )
);
\end{lstlisting}

Esta consulta obtiene los libros cuyos ejemplares aparecen registrados en la tabla de detalle de préstamos.

\subsubsection{Fase P4: Evolución del esquema y recuperación}

En esta fase se modifica la tabla \texttt{LIBRO}, agregando la columna \texttt{ISBN\_LIB}, modificando el tamaño del título y agregando una restricción única.

\begin{lstlisting}[style=sqlstyle]
ALTER TABLE LIBRO ADD ISBN_LIB VARCHAR2(20);

ALTER TABLE LIBRO MODIFY TIT_LIB VARCHAR2(100);

ALTER TABLE LIBRO ADD CONSTRAINT UQ_ISBN_LIB UNIQUE (ISBN_LIB);

UPDATE LIBRO SET ISBN_LIB = 'ISBN-001' WHERE COD_LIB = 'L01';
UPDATE LIBRO SET ISBN_LIB = 'ISBN-002' WHERE COD_LIB = 'L02';
UPDATE LIBRO SET ISBN_LIB = 'ISBN-003' WHERE COD_LIB = 'L03';
UPDATE LIBRO SET ISBN_LIB = 'ISBN-004' WHERE COD_LIB = 'L04';
UPDATE LIBRO SET ISBN_LIB = 'ISBN-005' WHERE COD_LIB = 'L05';

COMMIT;
\end{lstlisting}

La columna \texttt{ISBN\_LIB} permite almacenar un identificador adicional para cada libro. La restricción \texttt{UNIQUE} evita que se repita el mismo ISBN.

Finalmente, se realiza una prueba de recuperación con \texttt{FLASHBACK}.

\begin{lstlisting}[style=sqlstyle]
CREATE TABLE PRUEBA_FLASHBACK_BIB (
    ID_PRU      NUMBER(10) PRIMARY KEY,
    NOM_PRU     VARCHAR2(30)
);

INSERT INTO PRUEBA_FLASHBACK_BIB VALUES (1,'PRUEBA BIBLIOTECA');
COMMIT;

DROP TABLE PRUEBA_FLASHBACK_BIB;

FLASHBACK TABLE PRUEBA_FLASHBACK_BIB TO BEFORE DROP;

SELECT * FROM PRUEBA_FLASHBACK_BIB;
\end{lstlisting}

Con esta prueba se comprueba que una tabla eliminada puede recuperarse desde la papelera de reciclaje de Oracle.

\subsection{Recomendaciones}

Se recomienda ejecutar los scripts en orden, iniciando por las tablas base y luego las tablas que contienen claves foráneas. Esto evita errores de referencia al momento de crear o insertar datos.

Se recomienda verificar cada fase con consultas \texttt{SELECT} para comprobar que las tablas fueron creadas correctamente y que los datos se insertaron sin problemas.

También se recomienda no utilizar \texttt{DROP TABLE ... PURGE} cuando se desea recuperar una tabla mediante \texttt{FLASHBACK}, ya que esta opción elimina la tabla de forma definitiva.

La tabla \texttt{articulos} posee una clave foránea hacia \texttt{categorias}. Además, incluye una restricción \texttt{CHECK} para evitar que el stock sea negativo.

\begin{lstlisting}[language=SQL, caption={Creación de la tabla articulos}]
CREATE TABLE articulos (
    id_articulo NUMBER PRIMARY KEY,
    descripcion VARCHAR2(100) NOT NULL,
    id_categoria NUMBER NOT NULL,
    stock NUMBER NOT NULL,
    CONSTRAINT ck_articulos_stock CHECK (stock >= 0),
    CONSTRAINT fk_articulos_categorias 
        FOREIGN KEY (id_categoria)
        REFERENCES categorias(id_categoria)
);

\subsubsection{Tabla prestamos}

La tabla \texttt{prestamos} se relaciona con \texttt{usuarios} y \texttt{articulos}. También incluye una restricción \texttt{CHECK} que obliga a que la cantidad prestada sea mayor a cero.

\begin{lstlisting}[language=SQL, caption={Creación de la tabla prestamos}]
CREATE TABLE prestamos (
    id_prestamo NUMBER PRIMARY KEY,
    id_usuario NUMBER NOT NULL,
    id_articulo NUMBER NOT NULL,
    fecha_prestamo DATE NOT NULL,
    fecha_devolucion DATE,
    cantidad NUMBER NOT NULL,
    CONSTRAINT ck_prestamos_cantidad CHECK (cantidad > 0),
    CONSTRAINT fk_prestamos_usuarios 
        FOREIGN KEY (id_usuario)
        REFERENCES usuarios(id_usuario),
    CONSTRAINT fk_prestamos_articulos 
        FOREIGN KEY (id_articulo)
        REFERENCES articulos(id_articulo)
);
\end{lstlisting}

    p.id_prestamo,
    a.descripcion AS descripcion_articulo,

JOIN usuarios u

\subsection{Validación de INSERT incorrecto}

Durante la práctica se analizó el siguiente INSERT:

\begin{lstlisting}[language=SQL, caption={INSERT incorrecto analizado}]
INSERT INTO prestamo VALUES (200, 99, 1, SYSDATE, NULL, 1);
\end{lstlisting}

Este INSERT no es válido por dos razones. Primero, la tabla correcta se llama \texttt{prestamos}, no \texttt{prestamo}. Segundo, el usuario con ID 99 no existe en la tabla \texttt{usuarios}. Por lo tanto, si se corrige el nombre de la tabla, Oracle generaría un error de clave foránea porque no encuentra el usuario relacionado.

\begin{lstlisting}[language=SQL, caption={INSERT corregido}]
INSERT INTO prestamos 
VALUES (200, 10, 1, SYSDATE, NULL, 1);
\end{lstlisting}

\subsection{Actualización del usuario 10}

Se buscó al usuario con ID 10 y luego se actualizó su ubicación a la ubicación 101.

\begin{lstlisting}[language=SQL, caption={Sentencia corregida de actualización}]
UPDATE usuarios
SET id_ubicacion = 101
WHERE id_usuario = 10;
\end{lstlisting}

\subsection{Consulta de conteo de registros}

Se ejecutó una consulta para contar la cantidad de registros existentes en las tablas principales.

\begin{lstlisting}[language=SQL, caption={Conteo de registros por tabla}]
SELECT 
    (SELECT COUNT(*) FROM usuarios) AS usuarios,
    (SELECT COUNT(*) FROM articulos) AS articulos,
    (SELECT COUNT(*) FROM prestamos) AS prestamos
FROM dual;
\end{lstlisting}

Esta consulta usa subconsultas con \texttt{COUNT(*)} para contar cuántos usuarios, artículos y préstamos existen. La tabla \texttt{DUAL} se usa en Oracle para mostrar resultados calculados en una sola fila.

\subsection{Eliminación segura del usuario 20}

El usuario con ID 20, Pedro Sánchez, se dio de baja del sistema. Como tenía préstamos asociados, primero se intentó eliminarlo directamente para comprobar el error de integridad referencial.

\begin{lstlisting}[language=SQL, caption={Identificación de datos relacionados con el usuario 20}]
-- Se verifica que el usuario exista.

SELECT *
FROM usuarios
WHERE id_usuario = 20;

-- Se revisan los prestamos asociados al usuario 20.

SELECT *
FROM prestamos
WHERE id_usuario = 20;
\end{lstlisting}

\subsubsection{Intento incorrecto de eliminación}

\begin{lstlisting}[language=SQL, caption={Intento incorrecto de eliminar directamente al usuario 20}]
DELETE FROM usuarios
WHERE id_usuario = 20;
\end{lstlisting}

Este DELETE puede generar el error:

\begin{lstlisting}[language=SQL, caption={Error esperado por integridad referencial}]
ORA-02292: restriccion de integridad violada - registro secundario encontrado
\end{lstlisting}

El error ocurre porque el usuario posee registros dependientes en la tabla \texttt{prestamos}. Por lo tanto, primero se debe eliminar la información de la tabla hija y luego la información de la tabla padre.

\subsubsection{Eliminación correcta}

\begin{lstlisting}[language=SQL, caption={Eliminación correcta del usuario 20}]
-- Primero se eliminan los prestamos del usuario 20.

DELETE FROM prestamos
WHERE id_usuario = 20;

-- Luego se elimina el usuario 20.

DELETE FROM usuarios
WHERE id_usuario = 20;

-- Verificacion final.

SELECT *
FROM prestamos
WHERE id_usuario = 20;

SELECT *
FROM usuarios
WHERE id_usuario = 20;

COMMIT;
\end{lstlisting}

El orden correcto es:

\begin{center}
\textbf{prestamos $\rightarrow$ usuarios}
\end{center}

\subsubsection{Error ORA-00942}

\begin{lstlisting}[language=SQL, caption={Ejemplo de tabla mal escrita}]

La forma correcta es:

\begin{lstlisting}[language=SQL, caption={Corrección del nombre de tabla}]
DELETE FROM prestamos
WHERE id_prestamo = 102;
\end{lstlisting}

\subsubsection{Error ORA-00904}

Este error ocurre cuando se usa una columna que no existe en una tabla.

\begin{lstlisting}[language=SQL, caption={Ejemplo de columna inexistente}]
DELETE FROM usuarios
WHERE id_prestamo = 11;
\end{lstlisting}

La tabla \texttt{usuarios} no tiene la columna \texttt{id\_prestamo}. La forma correcta para eliminar un usuario sería usar \texttt{id\_usuario}.

\begin{lstlisting}[language=SQL, caption={Corrección usando la columna correcta}]
DELETE FROM usuarios
WHERE id_usuario = 11;
\end{lstlisting}

\subsubsection{Error ORA-02291}

Este error ocurre cuando se intenta insertar un registro que hace referencia a una clave foránea inexistente. Por ejemplo, registrar un préstamo para un usuario que no existe.

\begin{lstlisting}[language=SQL, caption={Ejemplo de error por clave foránea inexistente}]
INSERT INTO prestamos 
VALUES (200, 99, 1, SYSDATE, NULL, 1);
\end{lstlisting}

El usuario con ID 99 no existe en la tabla \texttt{usuarios}, por lo tanto, se rompe la integridad referencial.

\subsubsection{Error ORA-02292}

Este error ocurre cuando se intenta eliminar un registro padre que tiene registros hijos asociados.

\begin{lstlisting}[language=SQL, caption={Ejemplo de eliminación incorrecta}]
DELETE FROM usuarios
WHERE id_usuario = 20;
\end{lstlisting}

Si el usuario tiene préstamos asociados, primero se deben eliminar los préstamos y luego el usuario.

\section{Conclusiones}

Se concluye que el uso de claves primarias y claves foráneas permite mantener la integridad referencial dentro de una base de datos relacional. En la práctica se evidenció que Oracle no permite insertar datos relacionados con registros inexistentes ni eliminar registros padres que poseen registros hijos asociados.

Además, se comprobó que las operaciones DML deben ejecutarse en un orden correcto. Por ejemplo, para eliminar un usuario con préstamos registrados, primero se deben eliminar los préstamos y después el usuario. De esta manera se evitan errores como \texttt{ORA-02292}.

Finalmente, la práctica permitió reforzar el uso de sentencias \texttt{INSERT}, \texttt{UPDATE}, \texttt{DELETE} y \texttt{SELECT}, junto con el análisis de errores comunes en Oracle SQL.

\section{Recomendaciones}

Se recomienda verificar siempre los registros antes de ejecutar operaciones de actualización o eliminación, usando previamente una sentencia \texttt{SELECT}. Esto permite evitar cambios accidentales en la base de datos.

También se recomienda respetar el orden de inserción y eliminación de datos cuando existen claves foráneas. Primero deben insertarse los datos en las tablas padre y luego en las tablas hijas. Para eliminar, el orden debe ser inverso: primero las tablas hijas y después las tablas padre.

Finalmente, se recomienda escribir correctamente los nombres de tablas, columnas y tipos de datos, ya que errores pequeños como \texttt{VARACHAR2} en lugar de \texttt{VARCHAR2} pueden impedir la ejecución correcta del script.

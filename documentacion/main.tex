\subsection{Desarrollo de la Tarea}

\subsubsection{Descripción del caso de estudio}

La empresa de transporte puerta a puerta registra inicialmente toda la información en una sola hoja de cálculo con los campos: Num\_Viaje, Fecha, Cliente, Teléfono, Conductor, Vehículo, Placa, Origen, Destino, Valor y FormaPago.

Esta forma de almacenamiento genera redundancia, repetición de datos e inconsistencias, debido a que la información del cliente, conductor, vehículo y viaje se encuentra mezclada en una única estructura. Por esta razón, se aplicó normalización y se construyó un modelo relacional.

\subsubsection{Identificación de entidades}

A partir del caso de estudio se identificaron las siguientes entidades:

\begin{itemize}
    \item \textbf{CLIENTES:} almacena los datos de las personas que realizan reservas.
    \item \textbf{CONDUCTORES:} almacena los datos de los conductores asignados a los viajes.
    \item \textbf{VEHICULOS:} almacena los datos de los vehículos utilizados para el transporte.
    \item \textbf{VIAJES:} almacena la información del recorrido, fecha, origen, destino, valor y forma de pago.
    \item \textbf{RESERVAS:} relaciona a los clientes con los viajes y controla asiento y estado.
\end{itemize}

\subsubsection{Primera Forma Normal}

La Primera Forma Normal establece que los valores de cada campo deben ser atómicos, es decir, cada columna debe contener un solo dato. En el caso original, los campos se organizan en una estructura inicial sin grupos repetidos.

\begin{table}[H]
\centering
\caption{Modelo inicial en Primera Forma Normal}
\begin{tabular}{|p{3.5cm}|p{9cm}|}
\hline
\textbf{Relación} & \textbf{Atributos} \\
\hline
VIAJE\_GENERAL & Num\_Viaje, Fecha, Cliente, Teléfono, Conductor, Vehículo, Placa, Origen, Destino, Valor, FormaPago \\
\hline
\end{tabular}
\end{table}

\subsubsection{Segunda Forma Normal}

La Segunda Forma Normal elimina dependencias parciales. Para ello, se separan los datos de clientes, conductores y vehículos, ya que estos datos no dependen únicamente del viaje, sino de sus propias entidades.

\begin{table}[H]
\centering
\caption{Modelo en Segunda Forma Normal}
\begin{tabular}{|p{3.5cm}|p{9cm}|}
\hline
\textbf{Tabla} & \textbf{Atributos} \\
\hline
CLIENTES & id\_cliente, cedula, nombres, telefono, correo \\
\hline
CONDUCTORES & id\_conductor, cedula, nombres, licencia, telefono \\
\hline
VEHICULOS & id\_vehiculo, placa, tipo\_vehiculo, marca, capacidad, estado \\
\hline
VIAJES & id\_viaje, fecha, origen, destino, valor, forma\_pago, id\_conductor, id\_vehiculo \\
\hline
RESERVAS & id\_reserva, id\_cliente, id\_viaje, asiento, estado, fecha\_reserva \\
\hline
\end{tabular}
\end{table}

\subsubsection{Tercera Forma Normal}

La Tercera Forma Normal elimina dependencias transitivas. Por ejemplo, la placa depende del vehículo y no del viaje; el teléfono depende del cliente y no de la reserva; y los datos del conductor dependen de la tabla CONDUCTORES y no directamente de la tabla VIAJES. Con esta separación se reduce la redundancia y se mejora la integridad de los datos.

\subsubsection{Modelo relacional final}

El modelo relacional final está compuesto por las tablas obligatorias solicitadas en el examen: CLIENTES, CONDUCTORES, VEHICULOS, VIAJES y RESERVAS.

    \item CONDUCTORES 1 --- N VIAJES: un conductor puede realizar muchos viajes.
    \item VEHICULOS 1 --- N VIAJES: un vehículo puede ser asignado a muchos viajes.
\end{itemize}

\subsection{Implementación DDL}

Para implementar la base de datos se crearon las tablas CLIENTES, CONDUCTORES, VEHICULOS, VIAJES y RESERVAS. Cada tabla fue definida con restricciones de integridad para controlar la validez y relación de los datos.

\begin{lstlisting}[caption={Creación de la tabla CLIENTES}]
CREATE TABLE CLIENTES (
    id_cliente NUMBER PRIMARY KEY,
    cedula VARCHAR2(10) NOT NULL UNIQUE,
    nombres VARCHAR2(80) NOT NULL,
    telefono VARCHAR2(10) NOT NULL UNIQUE,
    correo VARCHAR2(100),
    CONSTRAINT chk_cliente_cedula CHECK (LENGTH(cedula) = 10),
    CONSTRAINT chk_cliente_telefono CHECK (LENGTH(telefono) = 10)
);
\end{lstlisting}

\begin{lstlisting}[caption={Creación de la tabla CONDUCTORES}]
CREATE TABLE CONDUCTORES (
    id_conductor NUMBER PRIMARY KEY,
    cedula VARCHAR2(10) NOT NULL UNIQUE,
    nombres VARCHAR2(80) NOT NULL,
    licencia VARCHAR2(20) NOT NULL UNIQUE,
    telefono VARCHAR2(10) NOT NULL,
    CONSTRAINT chk_conductor_cedula CHECK (LENGTH(cedula) = 10),
    CONSTRAINT chk_conductor_telefono CHECK (LENGTH(telefono) = 10)
);
\end{lstlisting}

\begin{lstlisting}[caption={Creación de la tabla VEHICULOS}]
CREATE TABLE VEHICULOS (
    id_vehiculo NUMBER PRIMARY KEY,
    placa VARCHAR2(10) NOT NULL UNIQUE,
    tipo_vehiculo VARCHAR2(40) NOT NULL,
    marca VARCHAR2(40) NOT NULL,
    capacidad NUMBER NOT NULL,
    estado VARCHAR2(20) NOT NULL,
    CONSTRAINT chk_capacidad_vehiculo CHECK (capacidad > 0),
    CONSTRAINT chk_estado_vehiculo CHECK (estado IN ('DISPONIBLE', 'MANTENIMIENTO'))
);
\end{lstlisting}

\begin{lstlisting}[caption={Creación de la tabla VIAJES}]
CREATE TABLE VIAJES (
    id_viaje NUMBER PRIMARY KEY,
    fecha DATE NOT NULL,
    origen VARCHAR2(80) NOT NULL,
    destino VARCHAR2(80) NOT NULL,
    valor NUMBER(8,2) NOT NULL,
    forma_pago VARCHAR2(30) NOT NULL,
    id_conductor NUMBER NOT NULL,
    id_vehiculo NUMBER NOT NULL,
    CONSTRAINT fk_viaje_conductor FOREIGN KEY (id_conductor) REFERENCES CONDUCTORES(id_conductor),
    CONSTRAINT fk_viaje_vehiculo FOREIGN KEY (id_vehiculo) REFERENCES VEHICULOS(id_vehiculo),
    CONSTRAINT chk_valor_viaje CHECK (valor > 0),
    CONSTRAINT chk_forma_pago_viaje CHECK (forma_pago IN ('EFECTIVO', 'TRANSFERENCIA', 'TARJETA'))
);
\end{lstlisting}

\begin{lstlisting}[caption={Creación de la tabla RESERVAS}]
CREATE TABLE RESERVAS (
    id_reserva NUMBER PRIMARY KEY,
    id_cliente NUMBER NOT NULL,
    id_viaje NUMBER NOT NULL,
    asiento NUMBER NOT NULL,
    estado VARCHAR2(20) NOT NULL,
    fecha_reserva DATE DEFAULT SYSDATE NOT NULL,
    CONSTRAINT fk_reserva_cliente FOREIGN KEY (id_cliente) REFERENCES CLIENTES(id_cliente),
    CONSTRAINT fk_reserva_viaje FOREIGN KEY (id_viaje) REFERENCES VIAJES(id_viaje),
    CONSTRAINT chk_asiento_reserva CHECK (asiento > 0),
    CONSTRAINT chk_estado_reserva CHECK (estado IN ('RESERVADO', 'PAGADO', 'ANULADO')),
    CONSTRAINT uk_viaje_asiento UNIQUE (id_viaje, asiento)
);
\end{lstlisting}

\subsection{Consultas SQL avanzadas}

En esta sección se desarrollaron las diez consultas SQL avanzadas solicitadas. Cada consulta se ejecutó por separado para evidenciar su funcionamiento dentro de Oracle SQL Developer.

\subsubsection{Consulta 1: Cliente que ha realizado el mayor número de reservas}

\textbf{Enunciado:} Mostrar el cliente que ha realizado el mayor número de reservas.

\begin{lstlisting}[caption={Consulta 1: Cliente con mayor número de reservas}]
SELECT *
FROM (
    SELECT 
        c.id_cliente,
        c.nombres AS cliente,
        COUNT(r.id_reserva) AS total_reservas
    FROM CLIENTES c
    INNER JOIN RESERVAS r
        ON c.id_cliente = r.id_cliente
    GROUP BY c.id_cliente, c.nombres
    ORDER BY total_reservas DESC
)
WHERE ROWNUM = 1;
\end{lstlisting}

Esta consulta relaciona CLIENTES con RESERVAS, cuenta las reservas de cada cliente y muestra el cliente con mayor cantidad de reservas.

\captura[0.95\linewidth]{img/07_consulta_01_cliente_mas_reservas.png}{Resultado de la consulta 1: cliente con mayor número de reservas.}

\textbf{Enunciado:} Mostrar el total de ingresos generados por cada viaje.

\begin{lstlisting}[caption={Consulta 3: Ingresos por viaje}]

    v.id_viaje,
    v.origen,
    v.destino,
    v.valor,
    COUNT(r.id_reserva) AS reservas_pagadas,

WHERE r.estado = 'PAGADO'
GROUP BY v.id_viaje, v.origen, v.destino, v.valor
ORDER BY v.id_viaje;
\end{lstlisting}

Esta consulta calcula el total de ingresos por viaje considerando las reservas que se encuentran en estado PAGADO.

\subsubsection{Consulta 9: Conductor cuyos viajes generan más ingresos acumulados}

\textbf{Enunciado:} Mostrar el conductor cuyos viajes generan más ingresos acumulados.

\begin{lstlisting}[caption={Consulta 9: Conductor con más ingresos acumulados}]

FROM (

\subsubsection{Consulta 10: Destinos con ingreso promedio superior al promedio general}

\textbf{Enunciado:} Mostrar los destinos cuyo ingreso promedio sea superior al promedio general de todos los viajes.

\begin{lstlisting}[caption={Consulta 10: Destinos con promedio superior}]
SELECT 
    destino,
    AVG(valor) AS ingreso_promedio_destino
FROM VIAJES
GROUP BY destino
HAVING AVG(valor) > (
    SELECT AVG(valor)
    FROM VIAJES
)
ORDER BY ingreso_promedio_destino DESC;

\subsubsection{Ejercicio 1: Bloque anónimo}

El bloque anónimo recibe el código de un viaje, obtiene su valor mediante SELECT INTO y muestra si corresponde a un viaje económico o premium.

\begin{lstlisting}[caption={Bloque anónimo para clasificar un viaje}]
SET SERVEROUTPUT ON;

DECLARE
    v_codigo_viaje NUMBER := 2;
    v_valor VIAJES.valor%TYPE;
BEGIN
    SELECT valor 
    INTO v_valor
    FROM VIAJES
    WHERE id_viaje = v_codigo_viaje;

        DBMS_OUTPUT.PUT_LINE('VIAJE ECONOMICO');
    ELSE
        DBMS_OUTPUT.PUT_LINE('VIAJE PREMIUM');
    END IF;

    DBMS_OUTPUT.PUT_LINE('Codigo de viaje: ' || v_codigo_viaje);
    DBMS_OUTPUT.PUT_LINE('Valor del viaje: ' || v_valor);
END;

\subsubsection{Ejercicio 2: Procedimiento REGISTRAR\_RESERVA}

El procedimiento almacenado REGISTRAR\_RESERVA recibe el cliente, el viaje y el asiento. Primero verifica si el asiento está disponible. Si se encuentra libre, registra la reserva y confirma la transacción. Si el asiento está ocupado, genera una excepción controlada.

\begin{lstlisting}[caption={Procedimiento almacenado REGISTRAR\_RESERVA}]
CREATE SEQUENCE seq_reserva
START WITH 11
INCREMENT BY 1;

CREATE OR REPLACE PROCEDURE REGISTRAR_RESERVA (
    p_id_cliente IN NUMBER,
    p_id_viaje IN NUMBER,
    p_asiento IN NUMBER
)
AS
    v_asiento_ocupado NUMBER;
BEGIN
    SELECT COUNT(*)
    INTO v_asiento_ocupado
    FROM RESERVAS
    WHERE id_viaje = p_id_viaje
    AND asiento = p_asiento;

    IF v_asiento_ocupado > 0 THEN
        RAISE_APPLICATION_ERROR(-20001, 'EL ASIENTO YA SE ENCUENTRA OCUPADO');
    ELSE
        INSERT INTO RESERVAS (
            id_reserva,
            id_cliente,
            id_viaje,
            asiento,
            estado,
            fecha_reserva
        )
        VALUES (
            seq_reserva.NEXTVAL,
            p_id_cliente,
            p_id_viaje,
            p_asiento,
            'RESERVADO',
            SYSDATE
        );

        COMMIT;

        DBMS_OUTPUT.PUT_LINE('RESERVA REGISTRADA CORRECTAMENTE');
    END IF;
END;
/
\end{lstlisting}

\subsubsection{Ejercicio 3: Cursor explícito}

El cursor explícito recorre todas las reservas registradas y muestra el cliente, viaje, asiento y estado.

\begin{lstlisting}[caption={Cursor explícito para recorrer reservas}]
DECLARE
    CURSOR c_reservas IS
        SELECT 
            c.nombres AS cliente,
            'Viaje ' || v.id_viaje || ': ' || v.origen || ' - ' || v.destino AS viaje,
            r.asiento,
            r.estado
        FROM RESERVAS r
        INNER JOIN CLIENTES c
            ON r.id_cliente = c.id_cliente
        INNER JOIN VIAJES v
            ON r.id_viaje = v.id_viaje
        ORDER BY r.id_reserva;

    v_cliente VARCHAR2(80);
    v_viaje VARCHAR2(150);
    v_asiento NUMBER;
    v_estado VARCHAR2(20);
BEGIN
    OPEN c_reservas;

    LOOP
        FETCH c_reservas 
        INTO v_cliente, v_viaje, v_asiento, v_estado;

        EXIT WHEN c_reservas%NOTFOUND;

        DBMS_OUTPUT.PUT_LINE('Cliente: ' || v_cliente);
        DBMS_OUTPUT.PUT_LINE('Viaje: ' || v_viaje);
        DBMS_OUTPUT.PUT_LINE('Asiento: ' || v_asiento);
        DBMS_OUTPUT.PUT_LINE('Estado: ' || v_estado);
        DBMS_OUTPUT.PUT_LINE('-----------------------------');
    END LOOP;

    CLOSE c_reservas;
END;
/
\end{lstlisting}

\subsubsection{Ejercicio 4: Trigger}

El trigger BEFORE INSERT sobre la tabla RESERVAS impide insertar reservas con asiento menor o igual a cero. Si ocurre una inserción inválida, se genera un error controlado con el mensaje ASIENTO INVALIDO.

\begin{lstlisting}[caption={Trigger para validar asiento}]
CREATE OR REPLACE TRIGGER trg_validar_asiento_reserva
BEFORE INSERT ON RESERVAS
FOR EACH ROW
BEGIN
    IF :NEW.asiento <= 0 THEN
        RAISE_APPLICATION_ERROR(-20002, 'ASIENTO INVALIDO');
    END IF;
END;

\end{lstlisting}

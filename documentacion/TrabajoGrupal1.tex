\subsubsection{General}
Desarrollar el esquema lógico de una base de datos para gestionar la información de cooperativas de transporte, socios, unidades, provincias, cantones, viajes, controles de calidad e incumplimientos, aplicando los principios del diseño de bases de datos.

\end{itemize}

\subsection{Instrucciones}

Se desea crear una base de datos para controlar los viajes de las cooperativas de transporte hacia las diferentes ciudades del país.

De las cooperativas de transporte se conoce el código, nombre, dirección y teléfono. Una cooperativa tiene muchos socios, pero cada socio puede pertenecer únicamente a una cooperativa.

Un socio tiene muchas unidades o buses, pero cada unidad pertenece solamente a un socio. De cada socio se conoce la cédula, nombre, apellido, dirección, teléfono y fecha de nacimiento. De cada unidad o bus se conoce el número de disco (ID), marca, año, placa y capacidad de pasajeros.

Una provincia tiene muchos cantones, pero cada cantón pertenece solo a una provincia. De cada provincia se conoce el código, nombre y ubicación. De cada cantón se conoce el código, nombre y referencia geográfica.

Muchos buses viajan a muchos cantones. De cada viaje se conoce el número de viaje, la fecha y hora de salida, la fecha y hora de llegada, el costo del asiento y la cantidad de pasajeros que viajan.

A los buses se les realizan controles de calidad anuales. Un bus pasa varios controles y cada control se aplica a un solo bus. Del control se conoce un código, la fecha del control, el tipo de control, el identificador del funcionario responsable del control y el resultado del control, el cual puede ser aprobado o reprobado.

Un control puede tener muchos incumplimientos. De cada incumplimiento se conoce el identificador, la descripción y el nivel de gravedad de la novedad.

\subsubsection{Identificación de entidades y atributos}

A partir del análisis del caso se identificaron las siguientes entidades principales del sistema:

\begin{itemize}
    \item \textbf{Cooperativa:} cod\_coo, nombre, dirección, teléfono.
    \item \textbf{Socio:} id\_soc, nombre, apellido, dirección, teléfono, fecha\_nacimiento, cod\_coo.
    \item \textbf{Unidad (Bus):} id\_bus, marca, año, placa, cap\_pas, id\_soc.
    \item \textbf{Provincia:} cod\_pro, nombre, ubicación.
    \item \textbf{Cantón:} cod\_can, nombre, ref\_geo, cod\_pro.
    \item \textbf{Viaje:} num\_via, fec\_hor\_sal, fec\_hor\_lleg, cost\_asi, cant\_pas, id\_bus, cod\_can.
    \item \textbf{Control de calidad:} cod\_con, fec\_con, tip\_con, id\_fun, result\_control, id\_bus.
    \item \textbf{Funcionario:} id\_fun, nom\_fun, ape\_fun.
    \item \textbf{Incumplimiento:} id\_inc, des\_nov, nivel\_gravedad, cod\_con.
\end{itemize}

\subsubsection{Relaciones y cardinalidades}

Las relaciones identificadas dentro del problema son las siguientes:

\begin{itemize}
    \item \textbf{Cooperativa -- Socio:} una cooperativa tiene muchos socios, pero cada socio pertenece a una sola cooperativa (1:N).
    \item \textbf{Socio -- Unidad:} un socio posee muchas unidades, pero cada unidad pertenece a un solo socio (1:N).
    \item \textbf{Provincia -- Cantón:} una provincia tiene muchos cantones, pero cada cantón pertenece a una sola provincia (1:N).
    \item \textbf{Unidad -- Viaje:} un bus puede realizar muchos viajes, pero cada viaje corresponde a un solo bus (1:N).
    \item \textbf{Cantón -- Viaje:} un cantón puede recibir muchos viajes, pero cada viaje tiene un solo destino (1:N).
    \item \textbf{Unidad -- Control de calidad:} un bus pasa varios controles, pero cada control se aplica a un solo bus (1:N).
    \item \textbf{Funcionario -- Control de calidad:} un funcionario puede realizar muchos controles, pero cada control es responsabilidad de un solo funcionario (1:N).
    \item \textbf{Control de calidad -- Incumplimiento:} un control puede registrar muchos incumplimientos, pero cada incumplimiento pertenece a un solo control (1:N).
\end{itemize}

    \item \textbf{FUNCIONARIOS}(\underline{id\_fun}, nom\_fun, ape\_fun)
    \item \textbf{CONTROLES}(\underline{cod\_con}, fec\_con, tip\_con, result\_control, id\_bus, id\_fun)
    \item \textbf{INCUMPLIMIENTOS}(\underline{id\_inc}, des\_nov, nivel\_gravedad, cod\_con)
\end{itemize}

\subsubsection{Reglas de integridad y negocio}

Para asegurar la consistencia de la base de datos, se plantean las siguientes reglas:

\begin{enumerate}
    \item Un socio debe pertenecer obligatoriamente a una cooperativa.
    \item Una unidad debe pertenecer obligatoriamente a un socio.
    \item Un cantón debe pertenecer obligatoriamente a una provincia.
    \item Cada viaje debe registrar fecha y hora de salida, fecha y hora de llegada, costo del asiento y cantidad de pasajeros.
    \item La capacidad del bus debe ser mayor o igual a la cantidad de pasajeros transportados en el viaje.
    \item Cada control debe estar asociado a un bus y a un funcionario responsable.
    \item Cada incumplimiento debe estar asociado a un control de calidad.
\end{enumerate}

\subsection{Resultados obtenidos}

Como resultado del desarrollo de la tarea, se obtuvo un esquema lógico compuesto por nueve tablas: COOPERATIVAS, SOCIOS, UNIDADES\_BUSES, PROVINCIAS, CANTONES, VIAJES, FUNCIONARIOS, CONTROLES e INCUMPLIMIENTOS.

El modelo elaborado permite representar de manera estructurada la información del sistema de transporte, respetando las relaciones de dependencia entre cooperativas, socios, buses, destinos, controles de calidad y novedades detectadas.

Asimismo, la solución propuesta facilita la aplicación de claves primarias y claves foráneas, permitiendo mantener la integridad referencial y reduciendo la redundancia en el almacenamiento de datos.
